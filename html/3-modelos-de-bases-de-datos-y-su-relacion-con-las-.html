Bases de datos como estructura de datos

Modelos de bases de datos y su relación con las estructuras de datos

Comprender los modelos jerárquico, de red, relacional y NoSQL, identificando su relación con árboles, grafos, tablas, listas y diccionarios.

Objetivo de aprendizaje

Analizar los principales modelos de bases de datos y su relación con las estructuras de datos, identificando las características de los modelos jerárquico, de red, relacional y NoSQL, para comprender cómo se organiza, almacena y relaciona la información, así como seleccionar el modelo más adecuado según las necesidades de un sistema informático.

Introducción

Las bases de datos permiten almacenar y administrar información de manera organizada. Sin embargo, no todas utilizan los mismos mecanismos para representar los datos ni establecen las mismas formas de relación entre sus elementos.

En el estudio de las estructuras de datos se analizan mecanismos como listas, árboles, grafos, diccionarios y tablas hash. Estas estructuras permiten organizar información siguiendo diferentes criterios y ofrecen características particulares para realizar operaciones de búsqueda, inserción, modificación y eliminación.

Los modelos de bases de datos aplican principios relacionados con estas estructuras para establecer cómo se representan los registros y sus relaciones.

Por ejemplo, una universidad puede organizar sus facultades y carreras mediante una estructura jerárquica, representar conexiones entre usuarios mediante un grafo o administrar estudiantes y asignaturas mediante tablas relacionadas.

Desde la perspectiva de las estructuras de datos, comprender estos modelos permite identificar cómo los conceptos estudiados anteriormente se utilizan en sistemas que necesitan almacenar y procesar información de manera persistente.

3.1. Concepto de modelo de base de datos

Un modelo de base de datos es un conjunto de conceptos, reglas y estructuras que establece cómo se representa, organiza, relaciona y manipula la información dentro de una base de datos.

Su propósito consiste en proporcionar una forma coherente de representar datos para facilitar su almacenamiento, consulta y administración.

El modelo determina cómo se describen los elementos de información, qué relaciones pueden establecerse entre ellos y qué operaciones permite realizar el sistema.

Elementos fundamentales

Elemento Descripción Ejemplo
Entidad Elemento sobre el que se almacena información. Estudiante
Atributo Característica que describe una entidad. Nombre, edad, carrera
Registro Conjunto de valores asociados a una entidad. Datos de un estudiante
Identificador Valor que distingue un registro. Código de estudiante
Relación Asociación entre elementos. Estudiante y asignatura
Restricción Regla que regula la validez de los datos. Identificador único
Operación Acción realizada sobre los datos. Insertar, consultar, actualizar

Importancia de los modelos de bases de datos

  • Representar adecuadamente las entidades de un sistema.
  • Establecer relaciones entre diferentes conjuntos de datos.
  • Facilitar la recuperación de información.
  • Reducir problemas de organización y duplicación innecesaria.
  • Definir mecanismos de identificación de registros.
  • Favorecer el mantenimiento y crecimiento de las aplicaciones.

Clasificación general de los modelos

Modelo jerárquico

Organiza registros mediante relaciones padre-hijo, semejantes a un árbol.

Modelo de red

Representa registros interconectados mediante múltiples relaciones.

Modelo relacional

Organiza información utilizando tablas y relaciones entre registros.

Modelos NoSQL

Incluyen documentos, clave-valor, columnas amplias y grafos.

Importante: el modelo lógico de una base de datos no es lo mismo que las estructuras físicas utilizadas internamente por el gestor. Una base de datos relacional puede utilizar árboles B para implementar índices, aunque su modelo lógico esté basado en tablas.

3.2. Modelo jerárquico y su relación con los árboles

El modelo jerárquico organiza los datos mediante una estructura de niveles, donde los registros se relacionan siguiendo un esquema padre-hijo.

Su organización se asemeja a un árbol, una estructura de datos no lineal formada por nodos conectados jerárquicamente.

Características principales
  • Organiza la información en diferentes niveles.
  • Utiliza relaciones padre-hijo.
  • Posee una estructura jerárquica definida.
  • Permite recorrer registros siguiendo rutas establecidas.
  • Resulta apropiado para dependencias jerárquicas claras.
  • Presenta limitaciones para relaciones muchos a muchos.

Ejemplo: organización universitaria

Universidad
↓
Facultad de Tecnología
↓
Desarrollo de Software
Redes Informáticas
Facultad de Administración
↓
Contabilidad
Administración de Empresas

Representación conceptual de una estructura jerárquica.

Relación con la estructura de datos árbol

Concepto en árboles Equivalente jerárquico
Raíz Registro principal
Nodo Registro de información
Padre Registro superior
Hijo Registro subordinado
Nivel Posición jerárquica
Recorrido Navegación entre registros

Ejemplo en Python

Una estructura jerárquica puede representarse mediante diccionarios y listas anidadas.

universidad = {
    "nombre": "Universidad Central",
    "facultades": [
        {
            "nombre": "Tecnología",
            "carreras": [
                "Desarrollo de Software",
                "Redes Informáticas"
            ]
        },
        {
            "nombre": "Administración",
            "carreras": [
                "Contabilidad",
                "Administración de Empresas"
            ]
        }
    ]
}

Para recorrer la estructura:

for facultad in universidad["facultades"]:
    print("Facultad:", facultad["nombre"])

    for carrera in facultad["carreras"]:
        print(" -", carrera)
Resultado esperado 
Facultad: Tecnología
 - Desarrollo de Software
 - Redes Informáticas
Facultad: Administración
 - Contabilidad
 - Administración de Empresas

Explicación del código

La variable universidad contiene un diccionario que representa la entidad principal. La clave facultades almacena una lista de diccionarios, cada uno con su nombre y sus carreras.

El primer ciclo for recorre las facultades y el segundo ciclo recorre las carreras correspondientes. Esto demuestra cómo combinar listas y diccionarios para representar una jerarquía.

Ventajas y limitaciones

Ventajas
  • Organización clara para jerarquías.
  • Navegación mediante rutas conocidas.
  • Representación natural de dependencias.
Limitaciones
  • Dificultad con relaciones complejas.
  • Dependencia de la jerarquía definida.
  • Menor flexibilidad para relaciones muchos a muchos.

Aplicaciones: organigramas, clasificaciones, categorías y estructuras organizativas. Estos ejemplos ilustran relaciones jerárquicas, aunque no necesariamente utilizan un gestor de bases de datos jerárquico.

3.3. Modelo de red y su relación con los grafos

El modelo de red organiza información mediante registros conectados a través de relaciones que permiten establecer múltiples asociaciones entre diferentes elementos.

A diferencia del modelo jerárquico, un registro puede participar en varias relaciones y no necesita depender de un único registro padre.

Características principales
  • Representa múltiples relaciones entre registros.
  • No depende de una única jerarquía.
  • Facilita conexiones complejas.
  • Admite asociaciones entre conjuntos de información.
  • Puede requerir mecanismos de navegación más complejos.

Ejemplo: estudiantes y asignaturas

Un estudiante puede inscribirse en varias asignaturas y cada asignatura puede tener varios estudiantes. Esto representa relaciones múltiples.

Las conexiones representan matrículas entre estudiantes y asignaturas.

Ana está relacionada con Programación y Bases de Datos; Carlos con Bases de Datos y Redes; y María con Programación.

Relación con la estructura de datos grafo

Concepto Interpretación
Vértice Estudiante o asignatura
Arista Relación de matrícula
Grafo Conjunto de elementos conectados
Recorrido Exploración de relaciones
Adyacencia Elementos directamente relacionados

Ejemplo en Python

matriculas = {
    "Ana": [
        "Programación",
        "Bases de Datos"
    ],
    "Carlos": [
        "Bases de Datos",
        "Redes"
    ],
    "María": [
        "Programación"
    ]
}

print(matriculas["Ana"])
Resultado 
['Programación', 'Bases de Datos']

Para recorrer todas las relaciones:

for estudiante, asignaturas in matriculas.items():
    print("Estudiante:", estudiante)

    for asignatura in asignaturas:
        print(" -", asignatura)
Resultado esperado 
Estudiante: Ana
 - Programación
 - Bases de Datos
Estudiante: Carlos
 - Bases de Datos
 - Redes
Estudiante: María
 - Programación

Explicación del código

El diccionario matriculas utiliza estudiantes como claves y listas de asignaturas como valores. El método items() permite recorrer ambos componentes.

Esta representación corresponde a una forma sencilla de lista de adyacencia utilizada para organizar grafos.

Ventajas
  • Representa múltiples relaciones.
  • Ofrece mayor flexibilidad que una jerarquía rígida.
  • Permite gestionar información interconectada.
Limitaciones
  • El diseño puede resultar complejo.
  • La navegación puede requerir conocimiento previo de las relaciones.
  • Algunos recorridos pueden ser extensos.

Aplicaciones: redes de telecomunicaciones, sistemas de transporte y sistemas que administran conexiones entre entidades. Estas necesidades también pueden atenderse con bases relacionales o de grafos.

3.4. Modelo relacional y organización mediante tablas

El modelo relacional organiza la información mediante relaciones que habitualmente se representan en forma de tablas.

Cada tabla contiene filas y columnas que permiten describir conjuntos de datos relacionados. Su fundamento se encuentra en el modelo propuesto por Edgar F. Codd en 1970.

Características principales
  • Organización mediante tablas.
  • Uso de atributos para describir entidades.
  • Identificación mediante claves.
  • Relaciones establecidas por claves foráneas.
  • Consultas y operaciones mediante SQL.
  • Restricciones de integridad.

Ejemplo: sistema académico

Tabla estudiantes

id_estudiante nombre carrera
1 Ana Desarrollo de Software
2 Carlos Redes Informáticas
3 María Desarrollo de Software

Tabla asignaturas

id_asignatura nombre
101 Programación
102 Bases de Datos
103 Redes

Tabla matrículas

id_matricula id_estudiante id_asignatura
1 1 101
2 1 102
3 2 103
4 3 101

La tabla matriculas establece relaciones entre estudiantes y asignaturas utilizando identificadores. De esta manera, la información puede organizarse sin repetir innecesariamente todos los atributos.

Relación con estructuras tabulares en Python

estudiantes = [
    {
        "id": 1,
        "nombre": "Ana",
        "carrera": "Desarrollo de Software"
    },
    {
        "id": 2,
        "nombre": "Carlos",
        "carrera": "Redes Informáticas"
    },
    {
        "id": 3,
        "nombre": "María",
        "carrera": "Desarrollo de Software"
    }
]

for estudiante in estudiantes:
    print(estudiante["nombre"])
Resultado 
Ana
Carlos
María

Esta lista de diccionarios representa registros de manera conceptual. Sin embargo, una base de datos relacional ofrece mecanismos adicionales como persistencia, restricciones, relaciones y consultas.

Introducción a SQL

SQL permite consultar información almacenada en bases de datos relacionales.

Consultar todos los estudiantes:

SELECT *
FROM estudiantes;

Seleccionar campos específicos:

SELECT nombre, carrera
FROM estudiantes;

Filtrar estudiantes por carrera:

SELECT nombre
FROM estudiantes
WHERE carrera = 'Desarrollo de Software';

Importante: las listas de Python mantienen el orden de sus elementos, mientras que las tablas relacionales no garantizan un orden de filas. Cuando una consulta requiere resultados ordenados, debe utilizarse ORDER BY.

Ventajas y limitaciones

Ventajas
  • Organización estructurada.
  • Relaciones entre entidades.
  • Consultas mediante SQL.
  • Restricciones de integridad.
Limitaciones
  • Requiere diseñar el esquema.
  • Algunas estructuras variables son difíciles de modelar.
  • Las consultas complejas pueden necesitar optimización.
  • Los cambios estructurales pueden requerir migraciones.

Aplicaciones: sistemas académicos, comerciales, bancarios y administrativos. Algunos gestores relacionales son SQLite, PostgreSQL, MySQL y Microsoft SQL Server.

3.5. Introducción a las bases de datos NoSQL

NoSQL agrupa diferentes enfoques de bases de datos que no se limitan al modelo relacional tradicional. El término suele interpretarse como Not Only SQL.

Estas tecnologías permiten representar información mediante modelos como documentos, clave-valor, columnas amplias y grafos.

Según la tecnología seleccionada, pueden facilitar el almacenamiento de información semiestructurada, esquemas flexibles y determinadas cargas de trabajo distribuidas.

Características generales

  • Representación flexible de información.
  • Almacenamiento mediante documentos o pares clave-valor.
  • Organización mediante columnas amplias.
  • Representación de relaciones utilizando grafos.
  • Posibilidad de distribución entre servidores, según el gestor.
  • Mecanismos de consulta adaptados al modelo utilizado.

Principales familias de bases de datos NoSQL

Clave-valor

Organiza información mediante claves asociadas con valores.

Ejemplo: Redis.

Documental

Utiliza documentos con campos y estructuras anidadas.

Ejemplo: MongoDB.

Columnas amplias

Utiliza filas identificadas por claves y columnas agrupadas.

Ejemplo: Apache Cassandra.

Grafos

Representa información mediante nodos y relaciones.

Ejemplo: Neo4j.

Ejemplo: catálogo de productos

Una tienda comercializa productos de categorías diferentes. Los electrónicos pueden incluir memoria y procesador, mientras que los muebles poseen dimensiones y materiales.

Documento de producto electrónico:

{
    "id": 101,
    "nombre": "Computadora portátil",
    "categoria": "Electrónica",
    "caracteristicas": {
        "memoria": "16 GB",
        "almacenamiento": "512 GB",
        "procesador": "Intel Core i5"
    }
}

Documento de mobiliario:

{
    "id": 102,
    "nombre": "Escritorio",
    "categoria": "Mobiliario",
    "caracteristicas": {
        "material": "Madera",
        "ancho_cm": 120,
        "alto_cm": 75
    }
}

Ambos documentos contienen información de productos, pero sus atributos son diferentes. El modelo documental permite representar esta variabilidad sin exigir que todos los documentos incluyan exactamente los mismos campos.

3.6. Relación de las bases de datos NoSQL con diccionarios, documentos y grafos

Las familias de bases de datos NoSQL presentan relaciones conceptuales con estructuras de datos utilizadas en programación.

Bases de datos clave-valor y diccionarios

Una base clave-valor puede compararse conceptualmente con un diccionario de Python.

usuarios = {
    "USR001": "Ana",
    "USR002": "Carlos",
    "USR003": "María"
}

print(usuarios["USR002"])
Resultado 
Carlos

Las claves permiten identificar los valores. En una base de datos clave-valor, el sistema gestor añade mecanismos para almacenar, recuperar y administrar la información.

Bases documentales y estructuras anidadas

Los documentos pueden contener campos, listas y objetos anidados, de forma semejante a la combinación de diccionarios y listas en Python.

estudiante = {
    "id": 1,
    "nombre": "Ana",
    "carrera": "Desarrollo de Software",
    "asignaturas": [
        {
            "codigo": "PRO101",
            "nombre": "Programación"
        },
        {
            "codigo": "BD102",
            "nombre": "Bases de Datos"
        }
    ]
}

print(estudiante["asignaturas"][0]["nombre"])
Resultado 
Programación

El acceso se realiza primero a la lista de asignaturas, después al elemento ubicado en la posición cero y finalmente al campo nombre.

Bases de datos de grafos

Las bases de grafos representan nodos y relaciones. Resultan útiles cuando las conexiones entre entidades son esenciales para resolver el problema.

Los nodos representan personas y las conexiones representan relaciones de amistad.

red_social = {
    "Ana": ["Carlos", "María"],
    "Carlos": ["Ana", "José"],
    "María": ["Ana", "José"],
    "José": ["Carlos", "María"]
}

print(red_social["Ana"])
Resultado 
['Carlos', 'María']

El diccionario representa una lista de adyacencia: cada persona está asociada a las personas con las que mantiene una conexión.

Comparación conceptual

Modelo NoSQL Estructura relacionada Representación
Clave-valor Diccionarios y tablas hash Clave asociada con valor
Documental Diccionarios y listas anidadas Documentos estructurados
Columnas amplias Mapas y estructuras agrupadas Filas y columnas agrupadas
Grafos Grafos y listas de adyacencia Nodos y conexiones

Estas relaciones son conceptuales. La implementación interna de un gestor NoSQL puede utilizar diferentes estructuras y combinar varios mecanismos de almacenamiento e indexación.

3.7. Comparación de los diferentes modelos de organización de datos

La selección de un modelo de base de datos depende de las características de la información y de las necesidades del sistema. Ningún modelo es superior en todos los escenarios.

Comparación general

Modelo Organización Estructura relacionada Aplicaciones
Jerárquico Padre-hijo Árboles Jerarquías definidas
De red Registros conectados Grafos Relaciones complejas
Relacional Tablas Relaciones tabulares Sistemas administrativos
Clave-valor Pares clave-valor Diccionarios, hash Sesiones y caché
Documental Documentos Diccionarios y listas Catálogos y perfiles
Columnas amplias Filas y columnas agrupadas Mapas distribuidos Grandes volúmenes
Grafos Nodos y relaciones Grafos Redes sociales

Criterios para seleccionar un modelo

Naturaleza de la información

Identificar si los datos son estructurados, variables o poseen múltiples relaciones.

Tipos de relaciones

Determinar cómo se conectan las entidades y qué relaciones deben representarse.

Operaciones de consulta

Analizar qué información se recuperará y qué consultas serán más frecuentes.

Integridad y consistencia

Establecer restricciones y garantías necesarias para las operaciones.

Volumen y crecimiento

Considerar cantidad de datos, rendimiento y necesidades de escalabilidad.

Caso de análisis: selección de un modelo

Aplicación A: gestión universitaria

Administra estudiantes, carreras, asignaturas, matrículas y calificaciones. El modelo relacional constituye una alternativa adecuada porque permite representar entidades y relaciones mediante tablas y claves.

Aplicación B: catálogo de productos

Almacena productos de diferentes categorías con atributos variables. Una base documental puede facilitar la representación de estructuras heterogéneas.

Aplicación C: análisis de relaciones sociales

Identifica conexiones entre personas y contactos compartidos. Una base de grafos facilita la representación y exploración de relaciones complejas.

Estos ejemplos demuestran que la selección del modelo debe basarse en los requisitos de información, las operaciones necesarias y las características del sistema.

Actividad de análisis y aplicación

Situación problemática: selección de modelos de bases de datos

Una empresa de desarrollo de software necesita implementar tres sistemas informáticos para diferentes organizaciones.

El primero administrará estudiantes, docentes, asignaturas y matrículas de una universidad.

El segundo gestionará una plataforma comercial con productos de características variables.

El tercero analizará conexiones entre usuarios de una comunidad digital para identificar relaciones y contactos compartidos.

Instrucciones

  1. Identificar las entidades y relaciones principales de cada sistema.
  2. Seleccionar un modelo de base de datos para cada aplicación.
  3. Justificar técnicamente las decisiones considerando la organización de los datos.
  4. Identificar qué estructuras de datos se relacionan con cada modelo seleccionado.
  5. Proponer una representación sencilla mediante tablas, diccionarios, listas o grafos.
  6. Explicar las ventajas y limitaciones de cada modelo.
  7. Analizar qué dificultades podrían surgir al utilizar un modelo inadecuado.
  8. Comparar las soluciones propuestas y explicar cómo influye el modelo en la recuperación de información.
Producto esperado

Un cuadro comparativo de los tres sistemas, acompañado de la representación de sus estructuras de información y una justificación técnica sobre la selección de los modelos de bases de datos.

Síntesis del subtema

Los modelos de bases de datos establecen diferentes mecanismos para organizar, representar y relacionar información.

El modelo jerárquico utiliza relaciones padre-hijo y presenta similitudes con los árboles, mientras que el modelo de red permite establecer conexiones más complejas entre registros, relacionadas conceptualmente con los grafos.

El modelo relacional organiza información mediante tablas y utiliza claves para representar asociaciones entre entidades.

Las bases de datos NoSQL incluyen diferentes familias, como clave-valor, documental, columnas amplias y grafos, que permiten representar información de acuerdo con distintas necesidades.

Desde la perspectiva de las estructuras de datos, estos modelos muestran cómo los conceptos de árboles, grafos, diccionarios, listas y estructuras tabulares permiten comprender diferentes mecanismos de organización de información.

La selección de un modelo debe considerar las características de los datos, las relaciones necesarias, los patrones de consulta y los requisitos de integridad, rendimiento y crecimiento del sistema.
