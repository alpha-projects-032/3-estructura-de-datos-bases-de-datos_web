Fundamentos de las bases de datos como estructura de datos

Comprender la relación entre las bases de datos y las estructuras de datos, sus mecanismos de almacenamiento y sus aplicaciones en el desarrollo de software.

Objetivo de aprendizaje

Comprender los fundamentos de las bases de datos y su relación con las estructuras de datos, identificando sus características, mecanismos de almacenamiento y ventajas frente a otras formas de organización de información, para reconocer su importancia en el desarrollo de aplicaciones informáticas.

Introducción

Los sistemas académicos, comerciales, bancarios y hospitalarios necesitan almacenar, consultar y modificar información. Durante el estudio de estructuras de datos se utilizan listas, diccionarios, pilas, colas y árboles para organizar información y ejecutar operaciones.

Cuando una aplicación también necesita conservar registros entre ejecuciones, mantener relaciones entre diferentes conjuntos de datos y garantizar determinadas reglas de integridad, las bases de datos resultan especialmente útiles.

Una base de datos no sustituye necesariamente a las estructuras de datos: su funcionamiento interno puede apoyarse en árboles, tablas hash, buffers y algoritmos de búsqueda, mientras que el programa sigue utilizando estructuras en memoria.

1.1 Concepto de base de datos

Una base de datos es un conjunto organizado de datos relacionados entre sí, almacenados de manera estructurada para facilitar su acceso, consulta, actualización y administración.

Su propósito es facilitar la gestión de información, manteniendo su disponibilidad y aplicando, según el sistema, mecanismos de integridad y consistencia.

Organización y relaciones

Los registros siguen una estructura y pueden vincularse con otros conjuntos de información.

Persistencia y acceso

Los registros pueden mantenerse entre ejecuciones y recuperarse mediante consultas.

Integridad y seguridad

Pueden definirse reglas de validez y controles de acceso a la información.

Ejemplo: registro de estudiantes

ID Nombre Carrera Edad
1 Ana Martínez Desarrollo de Software 20
2 Carlos López Redes Informáticas 22
3 María Hernández Desarrollo de Software 21
4 José Ramírez Ciberseguridad 23

A partir de estos registros se pueden buscar estudiantes por identificador, filtrar por carrera, actualizar datos, agregar nuevas filas y obtener estadísticas.

1.2 Relación entre bases de datos y estructuras de datos

Una estructura de datos organiza elementos para facilitar determinadas operaciones; una base de datos reúne información organizada y suele gestionarse mediante un sistema que ofrece persistencia, consultas, controles e integridad.

Idea clave: una base de datos no es simplemente una lista o una estructura aislada. Los gestores pueden utilizar varias estructuras y algoritmos para administrar información.
Aspecto Estructuras de datos Bases de datos
Propósito Organizar elementos para operar sobre ellos. Almacenar, relacionar y administrar información.
Ejemplos Listas, árboles, grafos, tablas hash. Tablas, documentos, índices y relaciones.
Conservación Depende de la implementación. Habitualmente almacenamiento persistente.
Consultas Mediante algoritmos del programa. Mediante consultas y mecanismos del gestor.
Integridad Normalmente se programa. Puede establecer restricciones de datos.

Ejemplo: lista de estudiantes en Python

estudiantes = ["Ana", "Carlos", "María", "José"]
print(estudiantes)
print(estudiantes[0])
estudiantes.append("Lucía")
print(estudiantes)

La lista conserva un orden y permite acceder a elementos o añadir registros. Si solo existe en la memoria del proceso, su contenido no queda guardado automáticamente al finalizar la aplicación.

Estructuras utilizadas por los gestores

Árboles

Organización de índices y búsqueda por rangos.

Tablas hash

Localización por claves en mecanismos especializados.

Listas y buffers

Resultados temporales y páginas almacenadas en memoria.

1.3 Almacenamiento en memoria y almacenamiento persistente

Los programas pueden mantener información temporalmente en memoria RAM o conservarla en dispositivos de almacenamiento no volátil.

En memoria

Permite procesar rápidamente variables y estructuras mientras se ejecuta el programa. Su contenido se pierde al terminar el proceso, salvo que se guarde por otro medio.

Ejemplo: una lista de productos en Python.

Persistente

Permite recuperar información entre ejecuciones mediante archivos, dispositivos o servicios de almacenamiento.

Ejemplo: una base de datos SQLite guardada en un archivo.

Ejemplo con lista de diccionarios

productos = [
    {"id": 1, "nombre": "Teclado", "precio": 25.00},
    {"id": 2, "nombre": "Mouse", "precio": 15.00}
]

print(productos)
Criterio En memoria Persistente
Medio RAM SSD, disco u otros medios
Duración Normalmente temporal Entre ejecuciones
Uso típico Cálculos, listas y resultados temporales Registros y archivos de bases de datos
Importante: también existen bases de datos en memoria y estructuras de datos persistentes. La distinción depende del diseño y la implementación, no solo del nombre de la tecnología.

1.4 Importancia de las bases de datos en el desarrollo de software

La gestión de información mediante bases de datos facilita el desarrollo de sistemas que requieren registros organizados, consultas, relaciones y reglas de validez.

Organización

Separar estudiantes, materias y matrículas en conjuntos relacionados.

Recuperación

Consultar registros por criterios y aprovechar índices cuando conviene.

Integridad

Definir identificadores únicos y relaciones válidas.

Concurrencia

Coordinar operaciones de múltiples usuarios mediante mecanismos del gestor.

Mantenimiento

Facilitar ampliaciones y cambios del sistema.

Escalabilidad

Planificar el crecimiento del volumen de datos y las consultas.

Caso de análisis: biblioteca universitaria

Una biblioteca administra libros, usuarios y préstamos. Una base de datos permite representar estos conjuntos de registros y responder consultas sobre disponibilidad, préstamos activos y devoluciones pendientes.

Conjunto Datos
Libros Código, título, autor, categoría
Usuarios Identificador, nombre, correo
Préstamos Código, usuario, libro, fechas

1.5 Ventajas frente a listas y diccionarios

Las listas y los diccionarios de Python son excelentes para almacenar y procesar información temporal o conjuntos manejables de elementos. Cuando se requieren persistencia, relaciones, restricciones y consultas complejas, un gestor de bases de datos puede facilitar el trabajo.

Lista de Python 
clientes = ["Ana", "Carlos", "María"]

Permite almacenar secuencias y recorrer elementos.

Diccionario de Python 
cliente = {
    "id": 1,
    "nombre": "Ana",
    "correo": "ana@ejemplo.com"
}

Representa entidades mediante pares clave-valor.

clientes = [
    {"id": 1, "nombre": "Ana"},
    {"id": 2, "nombre": "Carlos"},
    {"id": 3, "nombre": "María"}
]
Necesidad Listas / diccionarios Base de datos
Datos temporales Muy adecuados Posible
Guardar entre ejecuciones Requiere guardado adicional Soporte habitual
Relacionar registros Se programa Mecanismos específicos
Validar restricciones Se programa Restricciones del gestor
Consultas variadas Algoritmos personalizados Lenguajes e índices
Precisión técnica: una base de datos no siempre es más rápida que un diccionario. Acceder por clave a un diccionario de Python suele tener complejidad promedio O(1). La elección depende del problema, el tamaño, el acceso y la persistencia.

1.6 Aplicaciones prácticas de las bases de datos

Los sistemas de información utilizan bases de datos para manejar registros que deben conservarse y consultarse.

Sistemas académicos

Estudiantes, docentes, asignaturas, matrículas y calificaciones.

Sistemas comerciales

Productos, proveedores, inventarios y facturación.

Sistemas hospitalarios

Pacientes, citas, expedientes y resultados.

Comercio electrónico

Catálogos, usuarios, pedidos y existencias.

Ejemplo introductorio: Python y SQLite

SQLite permite crear una base de datos persistente mediante el módulo sqlite3 de la biblioteca estándar de Python.

import sqlite3

# Crear o abrir el archivo de base de datos
conexion = sqlite3.connect("universidad.db")

# Crear la tabla
conexion.execute("""
    CREATE TABLE IF NOT EXISTS estudiantes (
        id INTEGER PRIMARY KEY,
        nombre TEXT NOT NULL,
        carrera TEXT NOT NULL
    )
""")

# Insertar un registro con parámetros
conexion.execute(
    "INSERT INTO estudiantes (nombre, carrera) VALUES (?, ?)",
    ("Ana", "Desarrollo de Software")
)

# Confirmar los cambios
conexion.commit()

# Recuperar los registros
registros = conexion.execute(
    "SELECT * FROM estudiantes"
).fetchall()

for registro in registros:
    print(registro)

conexion.close()
¿Qué representa cada elemento?
  • Python: ejecuta la lógica de la aplicación.
  • SQLite: administra tablas y registros.
  • universidad.db: guarda la información de forma persistente.
  • commit(): confirma las modificaciones de la transacción.

Al ejecutar nuevamente el programa se insertará otro registro. El control de duplicados y las operaciones CRUD se abordarán en los temas posteriores.

Actividad de análisis y reflexión

Situación: una universidad almacena estudiantes, asignaturas, matrículas y calificaciones solo en listas y diccionarios. Cuando termina el programa, la información deja de estar disponible. También necesita consultas simultáneas y relaciones entre registros.

  3. ¿Qué información debe conservarse y por qué?
  4. ¿Cómo relacionarías estudiantes, asignaturas y matrículas?

Resultado esperado: justificar técnicamente cuándo utilizar una base de datos y cómo se complementa con las estructuras de datos en memoria.

Síntesis

Las bases de datos organizan, relacionan y administran información para que pueda recuperarse, modificarse y conservarse según las necesidades de un sistema.

Su funcionamiento puede apoyarse en estructuras como árboles, tablas hash, listas y buffers, así como en algoritmos de procesamiento y búsqueda.

Las bases de datos y las estructuras en memoria no son excluyentes: se complementan para resolver problemas de almacenamiento, rendimiento e integridad.
