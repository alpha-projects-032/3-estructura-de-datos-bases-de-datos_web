Subtema 2. Organización y representación de datos en bases de datos

Comprender cómo se estructuran, identifican y relacionan los datos para diseñar bases de datos organizadas, consistentes y eficientes.

Objetivo de aprendizaje

Comprender cómo se organizan y representan los datos dentro de una base de datos, identificando las diferencias entre su organización lógica y física, las características de las tablas, registros, campos, tipos de datos, claves primarias y relaciones, para diseñar estructuras que permitan almacenar y gestionar información de manera organizada, consistente y eficiente.

Introducción

Almacenar información no consiste únicamente en guardar valores en variables o archivos. También implica decidir cómo se organizan esos valores, qué características poseen, cómo se identifican y de qué manera se relacionan con otros datos.

En estructuras de datos utilizamos listas, diccionarios y árboles para organizar información. Las bases de datos aplican principios relacionados e incorporan modelos, reglas de integridad y mecanismos de almacenamiento persistente.

Por ejemplo, una universidad necesita representar estudiantes, docentes, asignaturas y matrículas sin duplicaciones innecesarias y con relaciones bien definidas.

2.1. Organización lógica y física de los datos

La organización lógica describe cómo se representan, estructuran y relacionan los datos sin depender de su ubicación física. Comprende entidades, atributos, tablas y relaciones.

En un sistema académico, por ejemplo, las entidades Estudiantes, Asignaturas y Matrículas se conectan mediante identificadores.

La organización física describe la forma real en que los datos se almacenan y recuperan: archivos, páginas, bloques, distribución de registros, índices y operaciones de lectura y escritura. SQLite, por ejemplo, puede mantener una base de datos persistente en un archivo y utilizar páginas y árboles B para organizar información.

La organización lógica define qué representa la información; la física determina cómo se almacena y accede a ella.

2.2. Concepto de tablas, registros y campos

En el modelo relacional, una tabla agrupa datos en filas y columnas. Un registro es una fila correspondiente a una instancia de la entidad y un campo es una columna que representa un atributo.

id_estudiante nombre edad carrera
1 Ana Martínez 20 Desarrollo de Software
2 Carlos López 22 Redes Informáticas
3 María Hernández 21 Desarrollo de Software
4 José Ramírez 23 Ciberseguridad

Esta tabla contiene cuatro registros y cuatro campos. En Python podemos simular su representación mediante una lista de diccionarios:

estudiantes = [
    {"id": 1, "nombre": "Ana Martínez", "edad": 20, "carrera": "Desarrollo de Software"},
    {"id": 2, "nombre": "Carlos López", "edad": 22, "carrera": "Redes Informáticas"},
    {"id": 3, "nombre": "María Hernández", "edad": 21, "carrera": "Desarrollo de Software"}
]

print(estudiantes[0]["nombre"])
Resultado: Ana Martínez. La lista agrupa registros; cada diccionario representa un registro y sus claves equivalen conceptualmente a los campos. Esta representación no incorpora automáticamente persistencia ni restricciones relacionales.

2.3. Tipos de datos utilizados en bases de datos

Los tipos de datos establecen qué valores pueden representarse y qué operaciones son apropiadas. La disponibilidad exacta depende del gestor.

Tipo Ejemplo Uso habitual
Entero 25 Edades, cantidades, identificadores
Real 85.75 Mediciones y promedios
Texto Ana Martínez Nombres, descripciones
Booleano Verdadero Estados lógicos
Fecha y hora 2026-10-14 Eventos y transacciones
Binario Archivo Imágenes y documentos

Clases de almacenamiento en SQLite

NULL — sin valor INTEGER — enteros REAL — decimales TEXT — texto BLOB — binario

SQLite no posee una clase booleana propia: se suelen utilizar enteros 0 y 1. Las fechas pueden almacenarse mediante texto, enteros o reales según una convención de la aplicación.

Selección de tipos en un inventario

Campo Tipo SQLite Justificación
id_producto INTEGER Identificador
nombre TEXT Descripción textual
precio_centavos INTEGER Evita redondeo binario en cantidades monetarias
existencia INTEGER Cantidad de unidades
disponible INTEGER 0 o 1 
producto = {
    "id_producto": 101,
    "nombre": "Teclado",

}

print(type(producto["id_producto"]))
print(type(producto["nombre"]))
print(type(producto["disponible"]))

Resultado: <class 'int'>, <class 'str'> y <class 'bool'>. Python y los sistemas gestores poseen reglas de tipos que deben distinguirse.

2.4. Identificación de registros mediante claves primarias

Clave primaria (PRIMARY KEY): campo o conjunto de campos que identifica de manera única cada registro de una tabla.
  • Sus valores no deben duplicarse.
  • Sus componentes no deben ser nulos.
  • Puede ser simple o compuesta.
  • Conviene que sea estable para facilitar las relaciones.
id_estudiante (PK) nombre carrera
101 Ana Martínez Desarrollo de Software
102 Carlos López Redes Informáticas
103 Ana Martínez Ciberseguridad

Dos estudiantes pueden compartir nombre; el identificador permite distinguirlos. Una clave natural utiliza información del dominio (p. ej., un código institucional estable). Una clave sustituta es creada especialmente para identificar registros.

CREATE TABLE estudiantes (
    id_estudiante INTEGER PRIMARY KEY,
    nombre TEXT NOT NULL,
    carrera TEXT NOT NULL
);

En una tabla ordinaria de SQLite que admite rowid, INTEGER PRIMARY KEY tiene un comportamiento particular: actúa como alias del identificador interno de fila.

2.5. Relaciones entre diferentes conjuntos de datos

Las claves foráneas (FOREIGN KEY) establecen referencias entre registros y permiten definir restricciones de integridad referencial.

Uno a uno (1:1)

Un empleado puede vincularse con un único expediente de configuración personal.

Uno a muchos (1:N)

Un departamento puede contar con varios docentes.

Muchos a muchos (N:M)

Varios estudiantes pueden inscribir varias asignaturas; se utiliza una tabla intermedia.

Ejemplo: estudiantes, asignaturas y matrículas

Ana cursa Programación y Bases de Datos; Carlos cursa Bases de Datos. La tabla intermedia evita almacenar listas de asignaturas dentro del registro de cada estudiante.

CREATE TABLE matriculas (
    id_matricula INTEGER PRIMARY KEY,
    id_estudiante INTEGER NOT NULL,
    id_asignatura INTEGER NOT NULL,
    FOREIGN KEY (id_estudiante)
        REFERENCES estudiantes(id_estudiante),
    FOREIGN KEY (id_asignatura)
        REFERENCES asignaturas(id_asignatura)
);

En SQLite debe habilitarse la aplicación de restricciones de claves foráneas para la conexión:

PRAGMA foreign_keys = ON;

2.6. Representación de información mediante estructuras tabulares

Un diseño tabular debe determinar entidades, atributos, identificadores y relaciones. Guardar todos los datos en una sola tabla puede causar redundancia e inconsistencias.

Ejemplo inicial: préstamos en una sola tabla

ID préstamo Estudiante Libro Autor Fecha
1 Ana Python Básico J. Pérez 2026-10-01
2 Carlos Estructuras de Datos M. López 2026-10-02
3 Ana Estructuras de Datos M. López 2026-10-03
Se repiten datos de estudiantes, títulos y autores. Si un libro cambia de información, puede ser necesario modificar varias filas, con riesgo de inconsistencia.

Propuesta: tablas separadas y relacionadas

Estudiantes

1 — Ana
2 — Carlos

Libros

101 — Python Básico
102 — Estructuras de Datos

Préstamos

1 — estudiante 1, libro 101
2 — estudiante 2, libro 102
3 — estudiante 1, libro 102

Esta separación reduce duplicaciones innecesarias, permite establecer claves y relaciones y facilita el mantenimiento.

Diferencia entre tabla y lista

estudiantes = ["Ana", "Carlos", "María"]
print(estudiantes[0])  # Ana

En una lista, la posición es parte de la estructura. En una tabla relacional, el orden de las filas no está garantizado: para obtener resultados ordenados se utiliza ORDER BY.

SELECT *
FROM estudiantes
ORDER BY nombre;

2.7. Ejemplos de organización de datos en sistemas reales

Gestión académica

Estudiantes, asignaturas, docentes y matrículas.

Relación: las matrículas vinculan estudiantes y asignaturas.

Inventario

Productos, categorías, proveedores y movimientos.

Relación: los movimientos se asocian con productos.

Atención de solicitudes

Clientes, solicitudes y empleados.

Relación: las solicitudes se vinculan con clientes y empleados.

En el último caso, una aplicación también puede utilizar una cola en memoria para procesar solicitudes en orden, mientras la base de datos conserva sus registros. Así, estructuras de datos y bases de datos se complementan.

Actividad de análisis y aplicación

Situación: una biblioteca universitaria administra libros, estudiantes y préstamos mediante archivos independientes. Existen dificultades para identificar usuarios, controlar ejemplares y consultar historiales.

Instrucciones:

  1. Identificar las entidades principales.
  2. Definir al menos cuatro campos por entidad con sus tipos de datos.
  3. Establecer una clave primaria para cada tabla.
  4. Determinar relaciones y claves foráneas.
  5. Representar al menos cinco registros de ejemplo distribuidos entre las tablas.
  6. Diferenciar los componentes de organización lógica y física.
  7. Justificar por qué convienen las tablas relacionadas frente a una única tabla.
  8. Explicar cómo listas y diccionarios de Python podrían procesar temporalmente los resultados.
Producto esperado: propuesta de diseño lógico con tablas, campos, tipos, claves y relaciones, más registros de ejemplo y justificación técnica.

Síntesis del subtema

La organización lógica representa entidades, atributos y relaciones; la organización física determina cómo se almacenan y recuperan los datos.

Las tablas organizan información mediante registros y campos. Los tipos de datos describen los valores; las claves primarias identifican registros, y las claves foráneas establecen relaciones que contribuyen a la integridad referencial.

Una organización adecuada reduce redundancias, facilita consultas y mantenimiento, y permite complementar las bases de datos con estructuras de Python como listas, diccionarios y colas.
