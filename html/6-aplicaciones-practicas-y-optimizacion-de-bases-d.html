Bases de datos como estructura de datos

Aplicaciones prácticas y optimización de bases de datos

Aplicar Python y SQLite para organizar información, implementar relaciones, mejorar búsquedas y mantener la integridad de los registros.

Objetivo de aprendizaje

Aplicar los conocimientos adquiridos sobre bases de datos y estructuras de datos mediante el diseño e implementación de soluciones utilizando Python y SQLite, identificando la importancia de las relaciones entre tablas, los índices, la integridad de la información y la eficiencia de las operaciones de búsqueda, para desarrollar aplicaciones que permitan almacenar, consultar y administrar registros de manera organizada y persistente.

Introducción

Las bases de datos desempeñan un papel fundamental en el desarrollo de aplicaciones informáticas porque permiten almacenar, organizar, relacionar y recuperar información de manera estructurada.

Durante los subtemas anteriores se estudiaron sus fundamentos, mecanismos de organización, modelos de representación, operaciones CRUD y procedimientos para implementar bases de datos mediante Python y SQLite.

Estos conocimientos permiten avanzar hacia la aplicación práctica y la optimización de las operaciones realizadas sobre los datos.

En el estudio de las estructuras de datos, la eficiencia de un algoritmo depende de factores como la cantidad de elementos, su organización y los mecanismos utilizados para acceder a ellos.

Por ejemplo, buscar un estudiante dentro de una lista puede requerir un recorrido secuencial. En cambio, un diccionario permite localizar valores mediante claves utilizando una tabla hash.

Las bases de datos también emplean estructuras especializadas para mejorar determinadas operaciones. Entre ellas se encuentran los índices, que pueden apoyarse en árboles B, árboles B+ o estructuras hash, dependiendo del sistema gestor.

En este subtema se analizarán estas características y se desarrollará una aplicación que integrará Python, SQLite, consultas SQL y criterios básicos de optimización.

6.1. Utilización de bases de datos en aplicaciones reales

Las bases de datos se utilizan en sistemas que necesitan conservar y administrar información de manera continua. Su implementación depende de los datos utilizados, las operaciones requeridas y los requisitos de integridad, almacenamiento y rendimiento.

6.2. Organización de información mediante tablas relacionadas

Una base de datos relacional permite separar información en diferentes tablas y establecer asociaciones entre registros. Este mecanismo facilita representar entidades y reducir la repetición innecesaria de datos.

Implementación de tablas relacionadas en SQLite

Primero se habilita la comprobación de claves foráneas en la conexión:

import sqlite3

conexion = sqlite3.connect("biblioteca.db")

conexion.execute("PRAGMA foreign_keys = ON")

Posteriormente se crean las tablas:

conexion.executescript("""
    CREATE TABLE IF NOT EXISTS usuarios (
        id_usuario INTEGER PRIMARY KEY,
        nombre TEXT NOT NULL,
        correo TEXT NOT NULL UNIQUE
    );

    CREATE TABLE IF NOT EXISTS libros (
        id_libro INTEGER PRIMARY KEY,
        titulo TEXT NOT NULL,
        autor TEXT NOT NULL
    );

    CREATE TABLE IF NOT EXISTS prestamos (
        id_prestamo INTEGER PRIMARY KEY,
        id_usuario INTEGER NOT NULL,
        id_libro INTEGER NOT NULL,
        fecha_prestamo TEXT NOT NULL,
        FOREIGN KEY (id_usuario)
            REFERENCES usuarios(id_usuario),
        FOREIGN KEY (id_libro)
            REFERENCES libros(id_libro)
    );
""")

conexion.commit()
conexion.close()

La tabla prestamos utiliza claves foráneas para relacionar usuarios y libros. La comprobación de claves foráneas debe habilitarse en cada conexión que necesite aplicar estas restricciones.

Consultas entre tablas mediante JOIN

SELECT
    usuarios.nombre,
    libros.titulo,
    prestamos.fecha_prestamo
FROM prestamos
INNER JOIN usuarios
    ON prestamos.id_usuario = usuarios.id_usuario
INNER JOIN libros
    ON prestamos.id_libro = libros.id_libro;

Con los datos de ejemplo insertados, la consulta devuelve:

Usuario Libro Fecha
Ana Martínez Python Básico 2026-10-01
Ana Martínez Bases de Datos 2026-10-03
Carlos López Estructuras de Datos 2026-10-05
Importancia de las relaciones
  • Reducen la duplicación innecesaria de información.
  • Permiten vincular registros de diferentes tablas.
  • Facilitan consultas que involucran varias entidades.
  • Contribuyen a mantener la integridad referencial.

6.3. Concepto de índices para mejorar las búsquedas

Un índice de base de datos es una estructura auxiliar que facilita la localización de registros mediante determinados campos, reduciendo potencialmente el trabajo necesario para ejecutar búsquedas.

Ejemplo conceptual

Una universidad almacena 50,000 estudiantes. Para localizar el identificador 32500, el sistema puede examinar registros o utilizar un índice adecuado que facilite su ubicación.

Sin un índice adecuado

Puede necesitar examinar numerosos registros de la tabla.

La búsqueda puede aumentar su costo al crecer la cantidad de datos.

Con un índice adecuado

Puede utilizar una estructura especializada para localizar registros.

Requiere almacenamiento y mantenimiento adicional.

Creación de un índice en SQLite

Supongamos que existe la siguiente tabla:

CREATE TABLE estudiantes (
    id_estudiante INTEGER PRIMARY KEY,
    nombre TEXT NOT NULL,
    carrera TEXT NOT NULL,
    correo TEXT
);

Se crea un índice sobre el campo correo:

CREATE INDEX idx_estudiantes_correo
ON estudiantes(correo);

Posteriormente se ejecuta una consulta:

SELECT *
FROM estudiantes
WHERE correo = 'ana@ejemplo.com';

El optimizador determina si conviene utilizar el índice para ejecutar la consulta.

¿Cuándo utilizar índices?

  • Cuando una tabla contiene numerosos registros.
  • Cuando existen búsquedas frecuentes sobre determinados campos.
  • Cuando se realizan consultas selectivas.
  • Cuando pueden mejorar combinaciones entre tablas.
  • Cuando favorecen determinados ordenamientos o filtros.

Importante: no es recomendable crear índices indiscriminadamente. Cada índice consume espacio y puede generar trabajo adicional durante inserciones, actualizaciones y eliminaciones.

En SQLite, INTEGER PRIMARY KEY en una tabla ordinaria compatible con rowid se relaciona directamente con el identificador interno de fila, por lo que normalmente no se necesita otro índice sobre ese campo.

6.4. Relación entre índices y estructuras de datos como árboles B y tablas hash

Los índices muestran una relación directa entre las bases de datos y las estructuras de datos. Para facilitar búsquedas, los sistemas gestores utilizan mecanismos de organización especializados.

Árboles B

Un árbol B es una estructura balanceada que mantiene claves ordenadas. Sus nodos pueden contener varias claves y múltiples hijos, lo que favorece el acceso a información organizada en páginas de almacenamiento.

Para buscar el valor 50, primero se examina la raíz. Al encontrarse entre 30 y 60, se continúa hacia el nodo central, evitando recorrer las demás ramas.

Árboles B+

Los árboles B+ constituyen una variante de los árboles B. Generalmente organizan las claves de búsqueda en nodos internos y concentran los valores o referencias correspondientes en las hojas.

Las hojas suelen estar enlazadas, lo que favorece consultas por rangos y recorridos ordenados.

Característica Árbol B Árbol B+
Organización Balanceada Balanceada
Claves Distribuidas entre nodos Nodos internos y hojas
Datos asociados Pueden aparecer en distintos niveles Habitualmente en hojas
Consultas por rangos Posibles Favorecidas por hojas enlazadas
Aplicación Almacenamiento e indexación Acceso ordenado e indexación

SQLite utiliza árboles B con características específicas de su formato interno. No todos los sistemas gestores utilizan exactamente la misma variante.

Tablas hash

Una tabla hash permite asociar claves con valores mediante una función hash. En condiciones habituales, una búsqueda exacta puede tener complejidad promedio O(1).

Los diccionarios de Python utilizan una implementación basada en tablas hash:

estudiantes = {
    101: "Ana",
    102: "Carlos",
    103: "María"
}

print(estudiantes[102])
Resultado 
Carlos

Comparación entre árboles e índices hash

Característica Árbol B Hash
Organización Claves ordenadas Claves transformadas por hash
Búsqueda exacta Eficiente Eficiente
Búsqueda por rangos Adecuada Generalmente inadecuada
Ordenamiento Puede favorecerlo No mantiene orden por clave

Particularidad de SQLite: sus índices ordinarios se basan en árboles B. SQLite no incorpora índices hash convencionales mediante CREATE INDEX.

6.5. Importancia de la integridad y consistencia de los datos

La integridad consiste en mantener información válida y coherente según las reglas definidas. La consistencia implica respetar las restricciones del sistema durante las operaciones realizadas.

Ejemplo: producto de inventario

Campo Valor
ID 101
Nombre Teclado
Precio 25.00
Existencia 15

Si la cantidad representa unidades disponibles, la aplicación no debería permitir existencias negativas. Tampoco debería aceptar precios negativos cuando las reglas del negocio no lo permiten.

Restricciones en SQLite

CREATE TABLE productos (
    id_producto INTEGER PRIMARY KEY,
    nombre TEXT NOT NULL,
    precio REAL NOT NULL CHECK(precio >= 0),
    existencia INTEGER NOT NULL CHECK(existencia >= 0)
);
PRIMARY KEY

Identifica registros de manera única.

NOT NULL

Impide almacenar un valor nulo.

CHECK

Establece condiciones que deben respetar los valores.

Ejemplo de restricción:

CHECK(existencia >= 0)

Integridad referencial

Las claves foráneas permiten establecer relaciones entre tablas y evitar referencias inválidas cuando se encuentran correctamente definidas y activas.

Transacciones y consistencia

Una venta puede requerir registrar una transacción comercial y disminuir las existencias de un producto. Ambas operaciones deben coordinarse para evitar inconsistencias.

Actualización protegida

UPDATE productos
SET existencia = existencia - 3
WHERE id_producto = 101
AND existencia >= 3;

Esta instrucción descuenta tres unidades únicamente cuando el registro indicado posee existencias suficientes. La aplicación también debe verificar que se haya afectado la fila esperada.

Buenas prácticas
  • Utilizar claves primarias y foráneas.
  • Definir restricciones sobre los valores.
  • Validar información antes de almacenarla.
  • Utilizar transacciones para operaciones relacionadas.
  • Evitar modificaciones sin condiciones.
  • Administrar adecuadamente los errores.

6.6. Comparación entre búsquedas secuenciales y búsquedas mediante índices

La eficiencia de una búsqueda depende de la cantidad de elementos, de su organización y de los algoritmos utilizados.

Búsqueda secuencial

La búsqueda secuencial examina los elementos uno por uno hasta encontrar el valor solicitado.

estudiantes = [
    {"id": 101, "nombre": "Ana"},
    {"id": 102, "nombre": "Carlos"},
    {"id": 103, "nombre": "María"},
    {"id": 104, "nombre": "José"}
]

buscado = 103

for estudiante in estudiantes:
    if estudiante["id"] == buscado:
        print(estudiante["nombre"])
        break
Resultado 
María

Complejidad temporal

O(1)

Mejor caso: primer elemento.

O(n)

Caso promedio.

O(n)

Peor caso: último o ausente.

Búsqueda mediante diccionario

estudiantes = {
    101: "Ana",
    102: "Carlos",
    103: "María",
    104: "José"
}

print(estudiantes[103])
Resultado 
María

El acceso por clave en un diccionario presenta complejidad promedio O(1) en condiciones habituales.

Búsqueda mediante índice de base de datos

CREATE INDEX idx_estudiantes_correo
ON estudiantes(correo);
SELECT *
FROM estudiantes
WHERE correo = 'ana@ejemplo.com';

Un índice balanceado puede reducir el trabajo de búsqueda. En términos generales, una búsqueda en árbol B suele presentar crecimiento logarítmico respecto a la cantidad de entradas.

Comparación de complejidades

Método Estructura Complejidad habitual
Búsqueda secuencial Lista O(n)
Acceso por clave Diccionario hash O(1) promedio
Índice balanceado Árbol B O(log n) general

Estas complejidades describen modelos teóricos. El tiempo real de una consulta SQL también depende del acceso a páginas, almacenamiento, caché, filtrados y combinaciones de tablas.

6.7. Desarrollo de un sistema básico de gestión de información utilizando Python y SQLite

Para integrar los conocimientos estudiados se desarrollará una aplicación sencilla de administración de productos utilizando Python y SQLite.

Funcionalidades del sistema
  • Crear la base de datos y la tabla.
  • Registrar productos.
  • Consultar el inventario.
  • Buscar por identificador.
  • Actualizar existencias.
  • Eliminar productos.
  • Crear un índice para una consulta frecuente.

Paso 1. Importar el módulo

import sqlite3

Paso 2. Crear la base de datos

def crear_base_datos():
    conexion = sqlite3.connect("inventario.db")

    conexion.execute("""
        CREATE TABLE IF NOT EXISTS productos (
            id_producto INTEGER PRIMARY KEY,
            nombre TEXT NOT NULL,
            categoria TEXT NOT NULL,
            precio REAL NOT NULL CHECK(precio >= 0),
            existencia INTEGER NOT NULL CHECK(existencia >= 0)
        )
    """)

    conexion.commit()
    conexion.close()

La función crea la tabla si no existe, definiendo campos y restricciones para mantener información válida.

Paso 3. Registrar productos

def registrar_producto(nombre, categoria, precio, existencia):
    conexion = sqlite3.connect("inventario.db")

    conexion.execute("""
        INSERT INTO productos
        (nombre, categoria, precio, existencia)
        VALUES (?, ?, ?, ?)
    """, (nombre, categoria, precio, existencia))

    conexion.commit()
    conexion.close()

Los marcadores ? permiten utilizar consultas parametrizadas y separar los valores de la instrucción SQL.

Paso 4. Consultar productos

def consultar_productos():
    conexion = sqlite3.connect("inventario.db")

    productos = conexion.execute("""
        SELECT *
        FROM productos
        ORDER BY id_producto
    """).fetchall()

    for producto in productos:
        print(producto)

    conexion.close()

La función utiliza SELECT para recuperar registros y un ciclo for para mostrarlos.

Paso 5. Buscar un producto

def buscar_producto(id_producto):
    conexion = sqlite3.connect("inventario.db")

    producto = conexion.execute("""
        SELECT *
        FROM productos
        WHERE id_producto = ?
    """, (id_producto,)).fetchone()

    conexion.close()

    return producto

La función recupera un registro mediante su identificador. Devuelve None cuando no encuentra el producto.

Paso 6. Actualizar existencias

def actualizar_existencia(id_producto, nueva_existencia):
    conexion = sqlite3.connect("inventario.db")

    conexion.execute("""
        UPDATE productos
        SET existencia = ?
        WHERE id_producto = ?
    """, (nueva_existencia, id_producto))

    conexion.commit()
    conexion.close()

La restricción CHECK de la tabla impide que la existencia almacenada sea negativa.

Paso 7. Eliminar un producto

def eliminar_producto(id_producto):
    conexion = sqlite3.connect("inventario.db")

    conexion.execute("""
        DELETE FROM productos
        WHERE id_producto = ?
    """, (id_producto,))

    conexion.commit()
    conexion.close()

La instrucción elimina el registro identificado, siempre que ninguna restricción aplicable lo impida.

Paso 8. Crear un índice

def crear_indice():
    conexion = sqlite3.connect("inventario.db")

    conexion.execute("""
        CREATE INDEX IF NOT EXISTS idx_productos_categoria
        ON productos(categoria)
    """)

    conexion.commit()
    conexion.close()

El índice sobre categoria puede mejorar determinadas consultas que utilizan este campo.

Paso 9. Ejecutar las funciones

Después de definir las funciones anteriores, se ejecuta el siguiente código:

crear_base_datos()

registrar_producto(
    "Teclado",
    "Periféricos",
    25.00,
    15
)

registrar_producto(
    "Mouse",
    "Periféricos",
    12.50,
    30
)

registrar_producto(
    "Monitor",
    "Pantallas",
    180.00,
    8
)

crear_indice()

print("Inventario registrado:")
consultar_productos()

print("Buscar producto:")
print(buscar_producto(2))

actualizar_existencia(2, 25)

print("Inventario actualizado:")
consultar_productos()

eliminar_producto(1)

print("Inventario después de eliminar:")
consultar_productos()

Síntesis del subtema

Las bases de datos permiten implementar soluciones informáticas que necesitan organizar, relacionar y conservar información de manera persistente.

Las tablas relacionadas facilitan representar entidades y asociaciones, mientras que las claves primarias y foráneas contribuyen a mantener la integridad de los registros.

Los índices son estructuras auxiliares que pueden mejorar determinadas búsquedas. Su funcionamiento está relacionado con árboles B y tablas hash, dependiendo de las características del sistema gestor.

La integridad y consistencia de la información requieren restricciones, validaciones y mecanismos de transacción para controlar las operaciones realizadas.

Las búsquedas secuenciales, los accesos mediante tablas hash y los índices balanceados presentan diferentes características de eficiencia.

Python y SQLite permiten integrar estos conceptos utilizando estructuras de datos en memoria, almacenamiento persistente, instrucciones SQL e índices.

El diseño adecuado de las estructuras y la selección de mecanismos de acceso son fundamentales para desarrollar sistemas capaces de administrar información de manera organizada, consistente y eficiente.
